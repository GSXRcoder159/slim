# Per-command notes (keep ≤ 40 lines each). Shipped top-level help is docs/help.txt.

------------------------------------------------------------------------
slim scan — inventory third-party packages (not a closed envelope)

Usage:
  slim scan [dir] [--json]

      --json             One schema-valid document on stdout

Exit 0 even when it finds candidates. Findings are data.
Never claims slim/closed. Example:  slim scan --json
------------------------------------------------------------------------
slim inspect — show call sites, envelope, and whether Slim will try

Usage:
  slim inspect <pkg> [--json] [--allow-unknown]

      --json             { schemaVersion, envelope, hash, decision, reason } on stdout
      --allow-unknown    generate-ready despite unknowns (never claimed closed)

Writes .slim/<pkg>/envelope.json. Exit 0 if Slim would try (closed, or
unsafe override). Exit 3 if the envelope is open/incomplete or refused
(report still printed). Example:  slim inspect lodash
------------------------------------------------------------------------
slim replace — write a verified slice and (usually) open a PR

Usage:
  slim replace <pkg>

      --budget-ms <n>    Extra-case quota n; wall bound n+2000ms startup+250ms shutdown (never the fake clock)
      --workers <n>      Fuzz worker threads (default: CPUs-1; 1 = in-process)
      --seed <n>         Deterministic fuzz seed
      --allow-flaky      Fuzz unseeded RNG packages (not production-ready evidence)
      --no-pr            Write files; no branch, commit, push, or PR
      --no-trace         Skip tests; static-only evidence (cannot claim trace-closed)
      --dry-run          Show the envelope and plan, write nothing (including traces)
      --out <dir>        Default: src/slim
      --keep-original    Do not uninstall the package
      --no-install       Rewrite package.json but skip lockfile refresh
      --llm              Force LLM even if catalog matches
      --template-only    Catalog only, no LLM
      --max-attempts <n> LLM repair loop (default 3)

Exit: 0 wrote (and PR opened if requested). 1 tests/fuzz/lockfile/merge-gate/repair exhausted/git commit/push/PR.
      3 Slim refuses this envelope, or no catalog and no LLM key. 4 missing gh and
      GITHUB_TOKEN when a PR is requested, missing origin, LLM HTTP/timeout,
      missing package manager, or traces required.
      `--force` does not skip tracing.
      `--json` is not supported. Exit 2 with usage on stderr and docs/error.schema.json on stdout.

Example:  slim replace lodash
------------------------------------------------------------------------
slim check — re-run standing tests; envelope still matches call sites

Usage:
  slim check [pkg] [--json]

      --json             One schema-valid document on stdout (docs/check.schema.json)

No network. Fails on semantic envelope drift, missing or malformed
evidence, missing standing/hardening tests, malformed envelopes, or a
failing standing/hardening suite. Prefers scripts.slim:evidence.
Empty replacements exit 0.
Example:  slim check
------------------------------------------------------------------------
slim watch — see if upstream advisories/releases touch your slice

Usage:
  slim watch
  slim upstream                (alias)

      --pr               Open a PR if a slice is exposed or unmapped
      --json             One schema-valid document on stdout (docs/upstream.schema.json)

Not a SaaS. Queries osv.dev and the npm registry from this machine.
OSV/npm outage, malformed response, timeout, or stale version → exit 4.
Never prints "slice not exposed" when a source could not be determined.
Unmapped advisories fail closed with a human-review artifact; no automatic rewrite.
Exposed slices regenerate only after oracle fuzz, standing tests, and hardening tests pass.
Example:  slim watch --json
------------------------------------------------------------------------
slim doctor — check Node, git, gh, slices, and the watch workflow

Usage:
  slim doctor [--strict] [--json]

      --strict           dirty working tree exits 4 (default: list it)
      --json             One schema-valid document on stdout (docs/doctor.schema.json)

Warnings (no gh, no watch workflow) do not fail. Node too old exits 4.
Example:  slim doctor
